## AprilTag shipment verification

- Browser port: <https://github.com/AliAlimohamad/apriltag-js>
- Pinned browser-port commit: `8569e26673b83d1b2baae68c953d83e1ba94fc4e`
- Pinned AprilRobotics source commit: `fb2a4096ec5f84b9ec18e501dfa129ffeaaf774e`
  (`3.4.3`)
- License: BSD-2-Clause; the complete upstream `LICENSE` and `NOTICE` ship
  beside the browser assets in `src/web/public/vendor/apriltag-js/`.

The browser port compiles the official AprilRobotics C detector to WebAssembly.
The application vendors its unmodified generated WebAssembly glue, binary,
worker, wrapper, and tag-family table. It does not copy the upstream playground,
overlay, or detector-manager UI. A small application-owned TypeScript client
provides runtime validation, bounded initialization and detection waits, and
single-frame backpressure. Detection stays in the worker so a slow frame cannot
block the operator interface.

The checked-in `tag36h11` generation table is mechanically generated by
`scripts/generate-apriltag-family.mjs` from `tag36h11.c` at the pinned official
commit. This keeps server-side vector label generation on the same 587 IDs as
the browser detector without loading browser-only WebAssembly into the server.

The detector receives only local pixel buffers and makes no network requests.
It is lazily loaded by Scanner rather than increasing the initial
operator-console bundle. The browser regression opens the built Scanner,
initializes the worker and WebAssembly module, detects a generated synthetic
tag upload, and resolves a ready order against synthetic server doubles.
