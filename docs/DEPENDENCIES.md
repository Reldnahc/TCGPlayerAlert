## AprilTag shipment verification

- Browser port: <https://github.com/AliAlimohamad/apriltag-js>
- Pinned browser-port commit: `8569e26673b83d1b2baae68c953d83e1ba94fc4e`
- Pinned AprilRobotics source commit: `fb2a4096ec5f84b9ec18e501dfa129ffeaaf774e`
  (`3.4.3`)
- License: BSD-2-Clause; the complete upstream `LICENSE` and `NOTICE` ship
  beside the browser assets in `src/web/public/vendor/apriltag-js/`.

The browser port compiles the official AprilRobotics C detector to WebAssembly.
The application vendors its unmodified generated WebAssembly glue, binary,
worker, wrapper, and tag-family table. It does not copy the upstream playground,
overlay, or detector-manager UI. A small application-owned TypeScript client
provides runtime validation, bounded initialization and detection waits, and
single-frame backpressure. Manual image detection stays in the browser worker
so a slow upload cannot block the operator interface. The long-running service
loads the same pinned, unmodified glue and WebAssembly binary into an isolated
Node VM context with a local-only asset response. That background detector
receives grayscale camera frames and makes no network requests.

The checked-in `tag36h11` generation table is mechanically generated by
`scripts/generate-apriltag-family.mjs` from `tag36h11.c` at the pinned official
commit. This keeps vector label generation, browser uploads, and background
detection on the same 587 identifiers.

The detectors receive only local pixel buffers and make no network requests.
The browser detector is lazily loaded by Scanner rather than increasing the initial
operator-console bundle. The browser regression opens the built Scanner,
initializes the worker and WebAssembly module, detects a generated synthetic
tag upload, and resolves a ready order against synthetic server doubles.

## node-av

- npm package: `node-av@6.1.1`
- Project: <https://github.com/seydx/node-av>
- Wrapper license: MIT
- Native media runtime: FFmpeg libraries under their applicable LGPL/GPL terms
- Purpose: enumerate and capture cameras in the long-running Node service on
  Windows, macOS, and Linux without requiring a separately installed FFmpeg
  executable or local compiler

The dependency is pinned and installs the host platform's prebuilt N-API and
FFmpeg artifacts. The application imports only the device, decoder, and scaler
API behind `CameraCaptureAdapter`; domain and shipment-resolution code do not
depend on NodeAV. Frames are requested at 1280×720 and ten frames per second
(a 100-millisecond capture cadence), converted to tightly packed grayscale
buffers, and discarded after detection. No camera frame is persisted or logged.

NodeAV declares optional WebRTC dependencies that the application does not
use. The root lockfile applies NodeAV's documented `neoip` and binary-data
compatibility overrides so the normal high-severity dependency audit remains
clean. Redistribution must retain and review the licenses of the exact FFmpeg
artifacts installed for each target platform.
